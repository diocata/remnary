## Real-history evaluation

The user authorized finding local histories. Seventeen Claude Code files, eleven Codex rollouts and eight Kiro snapshots yielded **32 conversations**. Three selected software-related ChatGPT views were then read through connected app tools and sent directly into encryption over standard input, for **35 total**. Partial/truncated coverage is retained and cannot overwrite a full export. Original files were not modified. Private data, the encrypted evaluation archive and keys are ignored by Git.

This evaluation found and fixed provider-prompt, inherited subagent metadata, task-notification, pasted-transcript and cumulative-snapshot attribution errors. Reimport, incremental analysis and SQLCipher integrity checks succeeded. Updated rules no longer extract the identified pasted-transcript case. No useful recurring pattern or user-confirmed insight was established. The user has delegated the usefulness review to the agent and requested no further questions. Source-grounded agent assessment will be recorded separately from independent test-user validation; the target (at least three of the top five useful) has **not passed**.

The user authorized a local model. Ollama 0.40.6 and Qwen 3.5 4B GGUF are installed on this 24 GiB Apple Silicon Mac. A dedicated loopback daemon reports cloud disabled. The default MLX variant could not provide structured output and was removed. After tightening grammar/citation choices, all 35 conversations completed the pipeline with **53 candidate extractions**, with no pending source-analysis failures or projection cleanup. Sources without eligible user text checkpoint empty results without model calls. Model interpretations still include exploratory questions mislabeled as preferences and one-time actions presented as preferences. These remain release-blocking quality findings, despite valid citations. [Model evaluation](local-model.md).

Processor v4 narrows local generation to explicit preferences, corrections and decision events, skipping known pasted-transcript messages. Exploratory option questions cannot supply preference/correction citations, including by quoting a shorter fragment. A reproducible ten-case synthetic semantic check now passes **10/10** in 37.9 seconds, with five candidate claims and all ten conversations checkpointed. Cases cover options versus choices, reversals, routine commands, assistant attribution, pasted transcripts, sensitive questions and Portuguese preferences. These hand-labeled development cases are small and informed the implementation; they are not an independent accuracy estimate. Uncertain options may be omitted rather than classified. An encrypted evaluation copy subsequently completed all 35 real sources with 48 candidates, but still mislabeled ordinary commands and one quoted assistant question. All 48 visible claims had only one supporting conversation; no useful recurrence was established. This contradicts a production-quality claim despite the synthetic score. The original private v3 findings remain unchanged as the comparison baseline. Processor v5 now limits structured question-panel messages to their user-answer spans; exact encoded source bytes remain intact. This source-attribution fix has regression coverage, but is not a general solution to semantic classification.

The larger Qwen 3.5 9B comparison also completed all 35 sources and selected its new results in a separate encrypted copy: 45 candidates (42 preferences, three corrections), all with one supporting conversation. The quoted-question attribution issue is fixed at the evidence boundary, but broader semantic errors remain. Larger non-reasoning inference alone did not solve the problem; these are development findings, not user-confirmed knowledge.

Schema 3 now persists active analysis heads per source revision/engine/model. Processor replacement retires obsolete automatic evidence, invalidates projections and preserves grounded human review/history. Upgrade and VACUUM regression tests pass. Distinct explicitly selected engines/models can contribute candidates concurrently; an already cached older processor is not silently reactivated.

The explicit `--replace-other-models` analysis option now selects a completed current processor/model and retires other Ollama automatic results only after an entirely successful run. Regression coverage preserves manual feedback/history and sources with no replacement result. Switching back is explicit; ordinary cache lookup never reactivates a retired result.

A release-binary recovery check killed backup, restore and plaintext conversion processes after observing nonempty private stages. All three left originals unchanged, published no incomplete destination, and retried successfully with integrity/search checks. This is observed SIGKILL coverage, not hardware power-loss testing or every publication boundary. Reproduce with `python3 scripts/check-recovery.py`.
