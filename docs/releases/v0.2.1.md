Import more of your local Codex history, including persisted desktop messages from different project directories and archived threads.

## Import desktop history

After replacing your executable with v0.2.1, use your existing Remnary archive:

```sh
remnary import "$HOME/.codex" --source codex-desktop
remnary sources
```

PowerShell: `remnary import "$HOME\.codex" --source codex-desktop`. Select your actual Codex home if it differs from the default. Linux users should pass their existing `--key-file` with archive commands.

- Reads the observed Codex v0.145 desktop SQLite history together with active and archived rollout files using read-only source access.
- Preserves source identities and project context, avoids duplicate rollout sources, and prevents partial projections from replacing fuller imported histories.
- Reports indexed threads with and without stored history. Analysis progress, source listings and the dashboard distinguish eligible user messages from worker threads and partial views.
- Keeps worker/review requests and unknown origins out of personal findings. Existing encrypted archives, reviews, backups and exclusion controls remain compatible; no archive migration is required.
- Includes clearer README instructions for Ollama versus built-in rules, rule matching and local-history coverage, plus the recent source organization improvements.

The app sidebar can include ChatGPT account chats and remote tasks absent from local storage. This importer cannot retrieve those missing histories; import a provider export or explicitly selected partial app snapshots instead. It does not promise complete account coverage. Database projections remain marked partial, and unsupported local schemas fail explicitly.

## Downloads and verification

Choose the archive for your operating system and CPU: Windows, Linux or macOS, on x64 or ARM64. Downloaded binaries require no Rust installation. Check the archive against its `.sha256` file or the combined `SHA256SUMS`; each archive includes `BUILD.json`, both project licenses and target-specific dependency notices.

Publication requires all six native builds, tests, Clippy, packaged-executable smoke checks and the advisory scan to pass. The local macOS suite passes 234 offline tests; opt-in live-model tests are not part of this release gate. No new model-quality claim is made.

Linux requires glibc 2.35+. macOS targets 13.0+ and is ad-hoc signed/unnotarized; Windows binaries remain unsigned. There is no automatic updater. See [platform policy](https://github.com/diocata/remnary/blob/main/docs/platforms.md) for tested environments and build prerequisites.
